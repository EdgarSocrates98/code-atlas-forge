# Review — lf-0038 (hybrid search + RRF)

**Veredito: APPROVED** — fusão RRF determinística, dedup por símbolo
com evidência preservada, degradação honesta sem vetorial, CLI
verificado verbatim.

## Findings (resolvidos durante a implementação)

1. **`_structural_hits` assinatura** — chamada inicial omitia `repo_id`
   (TypeError). Corrigido: `repo_for_root` + argumento posicional.
2. **Bug `tuple(f"rrf=...",)`** — iterava caracteres da string;
   evidência saía corrompida. Corrigido + teste pinado.
3. **Dedup por occurrence → por símbolo** — a spec exige "dedup por
   símbolo preservando evidências"; a primeira versão deduplicava por
   `occurrence_id` e `pkg.util.helper` aparecia 2× (def + uso). Agora
   a chave é `qualified_name` (identidade canônica disponível no hit);
   hit primário = melhor rank, desempate por occurrence_id.
4. **Teste legado `test_unknown_strategy_is_typed_error`** — assertia
   `"hybrid" not in capabilities`; atualizado para `vector` (estratégia
   realmente ausente) mantendo a verificação do erro tipado.

## Verificação (verbatim)

- `.venv/bin/pytest tests -q` → **400 passed**
- `.venv/bin/ruff check src tests` → All checks passed
- `.venv/bin/mypy src` → no issues (71 files)
- CLI: `search helper --strategy hybrid --json` →
  `ranking_version=rrf-k60-v1`; `pkg.util.helper` fundido
  `matched_fields=[lexical,structural]`, evidence `lexical:rank=1,
  structural:rank=1, rrf=0.032786`.

## Cobertura dos critérios

- RRF k=60 documentado (`RRF_K`, `rrf-k60-v1`); sem comparação de
  scores crus — só posições.
- Ranking preserva: estratégias participantes (`matched_fields`),
  rank por estratégia + score de fusão (`evidence`), identidade
  canônica (`qualified_name`), snapshot no envelope, span do primário.
- Dedup por símbolo com `hits` de todas as estratégias preservados.
- `hybrid` sem vetorial: `capabilities().vector=False`, funciona
  sobre lexical+structural+graph.
- CLI `--strategy {structural|lexical|graph|hybrid}` + `--snapshot`
  honrado via `SearchRequest.snapshot_id`; `--offset` mapeado para
  cursor com o mesmo fingerprint do engine.
- Comparativo medido: `test_hybrid_vs_baselines_union_coverage`
  pinha união dos baselines ⊂ hybrid.

## Riscos / limitações declaradas

- `fetch = 3×limit` (cap 200) por estratégia — hits fora dessa janela
  não participam da fusão; documentado no código.
- Diagnóstico `seed-not-found` do graph é suprimido no hybrid (semente
  opcional — lexical/structural cobrem a query); outros diags fluem.
- Sem provider vetorial ainda (lf-0039) — `vector=False` declarado.
