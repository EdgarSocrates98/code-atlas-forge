## Scope implementado

- `src/code_atlas/indexing/change_detector.py` — `detect_changes`
  (manifesto × último READY) → `ChangeSet` tipado. Kinds:
  ADDED/MODIFIED/DELETED/RENAMED/UNCHANGED (+ ANALYZER_CHANGED /
  RESOLVER_CHANGED no enum para granularidade futura). Regras:
  - **RENAMED somente por evidência**: path deletado + path adicionado
    com sha256 idêntico — nunca heurística de nome. O entry ADDED do
    path novo é substituído por RENAMED com `old_path` + razão.
  - Bump `parser:<lang>` → arquivos da linguagem viram MODIFIED com
    razão old→new; bump de analyzer não-linguístico (scanner/scan_mode)
    → todos os pré-existentes MODIFIED (conservador).
  - sha256 ausente em qualquer lado → MODIFIED ("cannot prove
    identical") — nunca UNCHANGED sem prova.
- `src/code_atlas/indexing/dependency_planner.py` —
  `InvalidationPlanner.plan(changeset, prior_import_edges,
  prior_parse_status)` → `IndexPlan`. Separação plano/execução
  respeitada: o plano é gerado e inspecionável (`to_json`, `counts`,
  `paths_for`, paths ordenados) antes de qualquer parse. Ações:
  `reparse`, `revalidate-relations`, `reuse`, `drop` — cada uma com
  `reason` determinística. Propagação:
  - fechamento transitivo sobre arestas IMPORTS resolvidas do snapshot
    anterior (cobre cadeias de re-export; ciclos seguros via `seen`);
  - imports sem alvo persistido → `_candidate_paths` (python
    absoluto/relativo com todos os prefixos; TS relativo com exts)
    intersecta paths afetados → revalida;
  - parse_status anterior `parse-failed`/`parsed-with-errors`/
    `unparsed` → revalida quando existe mudança real (deps
    desconhecidas → conservador);
  - `resolver_changes` → revalida relações de todos os `reuse`.
- `src/code_atlas/indexing/reuse.py` —
  - `reconstruct_universe`: reconstrói `ModuleCtx`s dos arquivos reuse
    a partir de `snapshot_file_symbols` (nids determinísticos → universo
    idêntico ao do parse original). `import_targets` não é
    reconstruído: ele só serve às refs do próprio arquivo, que não são
    reavaliadas (análise registrada).
  - `copy_occurrences_and_evidence` + `copy_relations`: copy-forward
    transacional com remap de FKs. Ocorrências `file` não são copiadas
    (nó de arquivo ganha ocorrência fresca a cada build); endpoints de
    relations remapeiam via occ_map OU lookup por
    `(logical_symbol_id, source_file_id)` — cobre arestas para
    reparseados/revalidados cujos símbolos são idênticos.
- `src/code_atlas/storage/store.py` — `conn` property +
  `snapshot_inventory` (com pior parse_status por arquivo),
  `module_import_edges` (IMPORTS mapeadas a paths),
  `snapshot_file_symbols`.
- `src/code_atlas/graph/builder.py` — `build(...,
  preserved_universe=)`; `_merge_preserved` injeta os ctxs reconstruídos
  nas tabelas (só resolução — nós/arestas dos reuse NÃO são reemitidos).
- `src/code_atlas/indexing/persist.py` — `external_occ`: alvos de
  arestas que vivem em módulos reutilizados amarram na ocorrência
  copiada (evita `edges_skipped` em relações válidas).
- `src/code_atlas/indexing/coordinator.py` — `index(..., incremental=)`:
  `_plan_incremental` (diff + plano + rede de segurança "reuse sem ctx
  → re-parse honesto"), `_parse_files(only=)`, `_persist_with_reuse`
  (copy-forward na mesma transação atômica — nenhuma semântica de
  publicação alterada), `last_plan` público para inspeção.
- `src/code_atlas/cli.py` — `code-atlas index --incremental`.

## Decisões/ausências registradas

- **`scheduler.py` não criado**: a ordenação de execução (copy
  occs/evi → persist_graph → copy relations) vive explícita em
  `_persist_with_reuse`; um módulo separado seria indireção sem conteúdo
  neste estágio.
- **`cache.py`/reuse de `ParseResult`**: fora de escopo por spec
  (lf-0020). O que existe aqui é o copy-forward de linhas — o mínimo
  necessário para o caminho `--incremental` ser real.
- **"rename preserves identity and symbol IDs"** (spec): interpretação
  registrada — a *classificação* preserva identidade de conteúdo
  (RENAMED por hash, não delete+add), o que ativa o tratamento correto
  de dependentes dos dois paths. Símbolos de um `.py` renomeado
  mudam de qname (`pkg.old.f` → `pkg.new.f`) porque o nome de módulo é
  derivado do path — novo símbolo é a verdade do modelo de identidade.
  `content_hash` das ocorrências é preservado para o arquivo renomeado.
- **No-op continua predominante**: digest+versões idênticos curto-
  circuitam ANTES do planejamento incremental (o caminho incremental
  só roda quando existe mudança real).
- **`force=True`** desativa incremental (reindex completo), conforme
  spec ("force must bypass" implicitamente pelo no-op path).
- `import_targets` de arquivos `reuse` não é reconstruído — verificado
  no resolver: `resolve_name(ctx, name)` usa `ctx.import_targets` do
  ctx do arquivo em resolução; o ctx de outro módulo só contribui
  `defines`/`modules`/`by_path`/`nid_mod`/`top_packages`.

## Gates de verificação (spec)

- `unchanged files reparsed sem justificativa` — NÃO ocorre: arquivos
  `reuse` sequer são abertos (`_parse_files(only=)`); `files_parsed=1`
  no teste de mudança isolada.
- `relação stale após mudança de dependência` — coberto:
  `test_incremental_importer_relations_reevaluated` (CALLS main→helper
  vira `unresolved` quando `helper` é removido do módulo importado).
- `plano inspecionável antes da execução` — `IndexPlan.to_json`
  serializável, counts por ação, razões ordenadas; `coord.last_plan`
  expõe o plano executado.
- `incremental ≡ full reindex` —
  `test_incremental_equals_full_reindex` compara nós/arestas canônicos
  (kind/qname/lang/path/status/hash + tipo/endpoints/status/confiança)
  entre snapshot incremental e `force` full do mesmo conteúdo.
- Planos: single-file change, rename+delete, analyzer bump, no-git,
  sem-snapshot-anterior, ciclos, transitividade, counts vs trabalho
  executado.

## Riscos restantes

- Blast radius conservador por design: uma mudança num módulo folha muito
  importado revalida transitivamente a cadeia de importadores — mais
  trabalho que o estritamente necessário, correto por spec
  ("correctness > speed").
- `missing_ctx` (reuse sem módulo persistido) vira re-parse — já cobre
  arquivos com status incompleto; refinamento fino fica para lf-0020.
- `_candidate_paths` cobre python abs/rel + TS relativo; imports TS bare
  (pacotes) permanecem external — se um arquivo local vier a
  shadow-á-los, a heurística de candidato pode precisar revisitar
  (registrado; sem caso real nos parsers atuais).
