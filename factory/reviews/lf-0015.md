## Audit findings (real bugs confirmed by code reading + tests)

- **0.2 scan→parse (P1, confirmado)**: `_parse_files` lia
  `Path.read_bytes()` — leitura separada e posterior ao hash do scan,
  seguindo symlinks sem contenção e sem conferir identidade. Arquivo
  alterado entre scan e parse produzia READY cujo digest descrevia bytes
  diferentes dos analisados.
- **0.3 evidências (P1, confirmado)**: `persist_graph` compactava
  `evi_row_ids` (só append quando `fid` existia) mas `e.evidence_index`
  indexa em `graph.evidence` não-filtrado — qualquer evidência pulada
  deslocava TODAS as referências seguintes → relações apontando para
  evidência errada, silenciosamente.
- **0.4 concorrência (P1, confirmado, dois sub-bugs)**:
  - `get_or_create_repository` era check-then-insert sem UNIQUE → dois
    indexadores criavam dois `repository_id` p/ o mesmo root_handle
    (grafos paralelos para o mesmo repo físico).
  - `BEGIN IMMEDIATE` fora do `try` e a própria criação de repo/job fora
    de proteção → `OperationalError: database is locked` propagava crua
    para o caller (sem `IndexOutcome`, sem FAILED inspecionável).

## Fixes implemented

- `scanner.py`: `_open_verified` extraído (resolve+contenção+O_NOFOLLOW+
  fstat regular); novo `read_file_verified` público para a leitura de
  parse — mesma disciplina do `_hash_file` (TOCTOU P1.1 do lf-0007).
- `coordinator._parse_files`: agora verifica `sha256(bytes) == f.sha256`
  após leitura verificada; divergência → `content-mismatch` parse-failed
  + evidence; `sha256=None` → `hash-unavailable`; symlink swap →
  `read-error`. Snapshot publica com perda explícita/auditável — nunca
  READY com identidade errada.
- `persist_graph`: `evi_row_ids` virou `dict[int,int]` (índice em
  `graph.evidence` → row id). Evidências filtradas não deslocam mais as
  referências das relações.
- `store.get_or_create_repository`: `INSERT ... SELECT WHERE NOT EXISTS`
  atômico — race-safe sem migração de schema.
- `coordinator`: `_acquire_write_lock` com backoff limitado (4×) antes de
  FAILED; setup repo/job protegido por try → `IndexOutcome` failed com
  `job_id=None` quando nem o job pôde ser registrado.
