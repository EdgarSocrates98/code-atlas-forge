## Scope implemented

- `src/code_atlas/resolvers/lsp/`:
  - `transport.py` — JSON-RPC 2.0 stdio com framing Content-Length.
    Leitura via `select`+`os.read` sobre o fileno (não BufferedReader) —
    thread daemon faz poll de 100ms no flag de fechamento: `close()`
    nunca trava num lock de buffer bloqueado. `recv` sempre com timeout;
    payload cap 16 MiB; framing/JSON inválido → `TransportError`.
  - `spawn.py` — **único** site de subprocess para LSP (mesmo padrão de
    confinamento do `gitbin.py`, whitelistado no audit de hardening):
    argv sem shell, binário via `shutil.which`, comando JAMAIS derivado
    do repo indexado (só `LspServerSpec` explícita), `enabled=False`
    por default, env minimizado, `MAX_LSP_SERVERS=4`, `release_server`
    faz kill+wait (zombie cleanup).
  - `lifecycle.py` — `LspClient`: spawn → `initialize` → negociação de
    capabilities (definition/references/documentSymbol/workspaceSymbol
    + serverInfo name/version) → requests com timeout obrigatório +
    `$/cancelRequest` → `shutdown`/`exit`. Crash detectado por EOF do
    transporte → `available=False`. `attach()` permite transporte
    injetado (testes in-process).
  - `adapter.py` — `LspResolver` (SemanticResolver, tier LSP): métodos
    só são chamados se o servidor anunciou a capability —
    `capability-unsupported` diagnostic senão. `Location{uri,range}` →
    path relativo ao `root_uri` → `by_path` nid (identidade file-level
    verificável); proveniência `lsp:<name>` + `serverInfo` no detail.

## Bugs reais encontrados e corrigidos

- **fd lifetime**: o transport guardava só `fileno()` — o objeto reader
  podia ser coletado e o fd fechado silenciosamente (transporte surdo,
  timeouts em 100% dos casos sob GC). Fix: referência mantida.
- **Deadlock de close**: `BufferedReader.close()` adquire lock que a
  thread leitora segura enquanto bloqueada em `readline()` do pipe —
  hang reproduzido com faulthandler. Fix: reescrita da leitura com
  `select`/`os.read` no fd.
- `available` exigia `_proc` — clients attachados (in-process) nunca
  ficavam disponíveis.
- `initialize` handshake agora respeita `spec.request_timeout_s` quando
  menor que `INIT_TIMEOUT_S`.
- `import subprocess` tipagem movida para alias `LspProcess` em
  `spawn.py` — audit de confinamento preservado.
