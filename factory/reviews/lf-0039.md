# Review — lf-0039 (optional vector search: sqlite-vec + bruteforce)

**Veredito: APPROVED** — contratos tipados, ADR-0022, extra `[vector]`
opt-in, cache por conteúdo+modelo, isolamento por snapshot, fusão
híbrida inclui ranking vetorial; instalação mínima intacta (0 deps).

## Findings (resolvidos durante implementação)

1. **Auditoria AST de SQL dinâmico** — `CREATE VIRTUAL TABLE ... f"FLOAT[{dim}]"`
   inline violava `test_no_dynamic_sql_in_execute_calls`. Corrigido:
   SQL em variável nomeada.
2. **Migration pin v7→v8** — `test_older_schema_db_opens_and_migrates`
   esperava 7; atualizado para 8 + nome da v8 no conjunto.
3. **`vector` agora existe** — 3 testes legados usavam "vector" como
   estratégia ausente / assumiam `caps.vector=False`. Atualizados:
   "quantum" como estratégia realmente inexistente; degradação sem
   vetorial via `enable_vector=False` (pinando `matched_fields` sem
   vector).
4. **Ruído de similaridade zero** — hits com cosseno 0 (ortogonais:
   arquivos/módulos sem tokens em comum) poluíam a página; filtrados
   com `vector-empty` info diag.

## Cobertura dos critérios

- Interfaces: `EmbeddingProvider`, `VectorIndex`, `VectorSearchResult`,
  `EmbeddingModelInfo`, `EmbeddingCache` (SqliteEmbeddingCache),
  `VectorCapability` — `search/vector/contracts.py`.
- ADR-0022: sqlite-vec vs FAISS/LanceDB/pgvector/Chroma/bruteforce —
  licença, portabilidade, peso, offline; decisão dupla implementação.
- Extra `[vector]` (`sqlite-vec>=0.1.6`) — instalação mínima intacta;
  ausência → backend bruteforce declarado em `capabilities().detail`.
- Cache por conteúdo: `embedding_cache` PK (model_id, model_version,
  content_hash) — rebuild só quando conteúdo OU modelo mudam
  (testado: `test_reindex_on_model_change`, versão estrutural).
- Provider local naïve (feature hashing documentado como baseline
  não-semântico); seam `EmbeddingProvider` p/ externo opt-in; zero
  egress por default.
- Sem vetorial (`enable_vector=False`): lexical/structural/graph/
  hybrid intactos (pinado).
- Fusão híbrida: `rankings["vector"]` entra no RRF quando habilitado.
- Granularidade sintática: index_text = qualified_name + signature +
  docstring (nunca chunk fixo).

## Riscos / limitações declaradas

- Provider naïve NÃO é semântico (sinônimos não aproximam) — baseline
  honesto documentado; troca de modelo = nova `EmbeddingModelInfo`.
- Bruteforce é O(n·dim) por query — aceitável em repos médios; extra
  `[vector]` dá KNN nativo quando instalado (não testado aqui:
  sqlite-vec ausente no ambiente — código caminho marcado).
- Embeddings materializam lazily na 1ª query vetorial/híbrida do
  snapshot (`embeddings_built=N` na evidence — custo visível).
