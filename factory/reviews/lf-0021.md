# Review — lf-0021 (git-aware change intelligence)

## Veredito: ACCEPTED

## O que foi entregue

- **Identidade lógica** (`discovery/identity.py`): `identity_key` por
  prioridade `git-remote:<url>` → `git-root:<sha raiz>` → `path:<root>`.
  `probe_git` agora captura `remote_url` (config remote.origin.url) e
  `root_commit` (`rev-list --max-parents=0 HEAD`, menor sha ordenado
  para históricos multi-raiz). `GitInfo` estendido — campos ficam fora
  do manifest (digest estável).
- **Schema v5**: `repositories.identity_key` UNIQUE + `snapshots.dirty`.
  Migração backfill `path:<root_handle>` em repos pré-v5.
- **Store**: `get_or_create_repository(identity_key, root_handle)` —
  lookup por identidade, `root_handle` atualizado a cada index
  (diagnóstico); `INSERT OR IGNORE` + UNIQUE fecha a race. `insert_snapshot`
  grava `dirty`; `repository_id_for` aceita identity_key **ou**
  root_handle (compat).
- **Coordinator**: ikey derivada do `scan.git`; snapshot grava
  `dirty=scan.git.dirty`. CLI `init` usa `identity_key_for_root`
  (probe sem scan).
- **Testes golden** (`test_git_intelligence.py`, 15): repos git reais
  via `gitbin` — rename `git mv` e filesystem-only, delete, dirty
  worktree (dirty=1 + digest distinto + mesmo commit_sha), branch
  switch (feat.py isolado por revisão), detached HEAD, sem `.git`
  (identidade `path:`), worktree (`.git` arquivo), case-rename (POSIX,
  skip win32), ignorados após branch switch, realocação preservando
  `repository_id`, dois clones compartilhando identidade, reexport +
  dep removida → importador revalidado (CALLS vira unresolved).

## Achados durante implementação (decisões honestas)

1. **Ignorado é propriedade da revisão**: após `checkout main`, o
   `.gitignore` sai → `ignored.py` vira untracked-não-ignorado e entra
   no inventário. Comportamento correto de `git ls-files` — o teste
   documenta a semântica por revisão, não por path.
2. **Watcher externo**: o ambiente roda um daemon que escreve
   `graphify-out/` em dirs com .py — `_inv_paths` filtra esse prefixo
   para asserções estáveis (ruído de ambiente, não bug do indexer).
3. **`get_or_create_repository` atômico**: substitui check-then-insert
   por `INSERT OR IGNORE` sobre `UNIQUE(identity_key)` — race do
   lf-0015 finalmente fechada na fonte.
4. **Dirty ≠ commit limpo**: snapshot dirty grava `commit_sha` do HEAD
   + `dirty=1` — conteúdo indexado nunca é apresentado como revisão
   limpa.

## Riscos restantes

- `identity_key` por remote URL é sensível a normalização (http vs ssh
  vs trailing `.git` não são unificados) — documentado como
  comportamento, não bug; múltiplos remotes ficam fora de escopo.
- `graphify-out` do watcher pode poluir inventários de usuários deste
  ambiente — mitigação futura: exclude-dir configurável (fora de escopo).
