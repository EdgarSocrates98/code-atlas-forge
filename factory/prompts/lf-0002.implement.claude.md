        # Grill Gate

- Owner: repository operator; behavior contract fixed by Blueprint §4 (`discovery`) and Master Prompt Fase 2.
- Problem: every later cycle depends on a safe, reproducible file inventory that respects git ignores and never touches untrusted content.
- Out of scope: AST parsing, symbol extraction, SQLite persistence of the inventory (lf-0003 wires that), CLI `index` command (lf-0004). Scanner returns data structures, not DB rows.
- Review failure: symlink escape outside root; `.gitignore` ignored when git present; secrets/keys included in inventory; crash on binary/huge/invalid-UTF-8 file; manifest differs between two identical runs.
- Riskiest assumption: git binary + `.git` dir both absent must still yield a usable scan — fallback ignore matching is best-effort and must be labeled as such in the manifest.
- Smallest acceptable: scanner walks root, classifies git state, applies ignore rules, hashes files, enforces limits, emits a deterministic manifest; all edge cases covered by tests with temp fixtures.

# Context

Blueprint ADR-014 treats the indexed repository as untrusted. The scanner is the security perimeter: it decides what enters the inventory. Master Prompt Fase 2 requires git-aware manifest, worktree/branch/HEAD/dirty detection, language-by-extension identification, sha256 fingerprints, canonical relative POSIX paths, defensive ignores, hard limits, and zero execution of repo code.

# Acceptance Criteria

- `code_atlas.discovery` exposes a scanner that, given a root path, returns a `ScanResult`/manifest object listing `SourceFile`-shaped records: normalized relative POSIX path, language guess, size_bytes, sha256, ignored flag.
- Git detection: branch, HEAD commit SHA, clean/dirty, worktree vs normal, and explicit "git absent" mode that still scans. When git binary available and `.git` exists, tracked/untracked classification uses `git ls-files`/`git status`; `.gitignore` honored via `--exclude-standard` semantics.
- Pure-python fallback when git binary missing: applies `.gitignore` patterns best-effort plus atlas default ignores, and marks the manifest with the degraded mode.
- Default ignore set: `.git`, `node_modules`, `__pycache__`, `.venv`/`venv`, `dist`, `build`, `.idea`, `.vscode`, caches, plus secret patterns (`.env*`, `*.pem`, `*.key`, `id_rsa*`, `credentials*`, `*.p12`, `*.pfx`) — secrets are excluded from hashing/inventory entries and recorded only as a count.
- Symlinks never followed outside root; a symlink pointing outside is recorded as a warning, not traversed. Circular links cannot loop the scan.
- Hard limits enforced with typed errors/warnings: max file count, max file size for hashing (oversize files inventoried with `hashed: false`, not read), max depth, optional scan timeout; Ctrl-C leaves a partial result marked partial.
- Binary files, malformed UTF-8, huge files, files with spaces/Unicode/NFC-vs-NFD names, nested `.gitignore`, and case-variant paths handled without crash; paths normalized to canonical relative POSIX.
- Manifest is deterministic: identical input tree produces identical manifest bytes (sorted paths, no timestamps inside the manifest body — run metadata kept separate).
- Scanner never executes, imports, or shells out to code found in the scanned repo; only `git` binary invocations against the root are permitted.
- Tests: empty dir, basic git repo, no-git dir, nested gitignore, ignored+secret files, symlink escape, unicode/space names, oversized file, malformed UTF-8, limit breaches, interrupted scan, determinism double-run.

# Constraints

- Do not write to the scanned repo; do not persist to DB (lf-0003).
