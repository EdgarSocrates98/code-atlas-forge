        # Grill Gate

- Owner: repository operator; entity set and enum vocabularies fixed by Blueprint §5/§6 — do not add or rename concepts.
- Problem: Cycle 1 must prove the snapshot state machine (BUILDING → READY / FAILED, prior READY preserved) and versioned schema before intelligence cycles build on it.
- Out of scope: real symbol/relation population (schema exists, writers for symbols are stubs-free empty paths exercised only by contract tests), FTS population, search queries, graph algorithms, LSP/SCIP.
- Review failure: SQL built by string concatenation of user input; migration that can't re-run cleanly; FAILED index attempt destroying or mutating the previous READY snapshot; FK violation possible; missing provenance fields on Relation/Evidence.
- Riskiest assumption: single-writer SQLite with WAL + busy timeout is sufficient for Cycle 1 concurrency — accepted per ADR-006; must be proven by a concurrent-reader test.
- Smallest acceptable: dataclass contracts + enums, migration runner, schema with all Blueprint tables, atomic inventory publish into a snapshot, idempotent re-index of identical inventory.

# Context

Blueprint §5 defines the canonical model: `Repository`, `Snapshot`, `SourceFile`, `LogicalSymbol`, `SymbolOccurrence`, `Relation`, `Evidence`, `IndexJob` — with logical identity separated from per-snapshot occurrence, `confidence_class` (`resolved`, `syntactic`, `heuristic`, `inferred`), `resolution_status` (`resolved`, `ambiguous`, `unresolved`, `external`), and edge vocabulary (`CONTAINS`, `DEFINES`, `IMPORTS`, `CALLS`, `IMPLEMENTS`, `EXTENDS`, `REFERENCES`, `CONFIGURES`, `TESTS`). §6 mandates SQLite WAL, migrations, single writer, parameterized queries, atomic READY publication.

# Acceptance Criteria

- `code_atlas.contracts.models` defines dataclasses (stdlib) for all eight entities with the Blueprint fields, including `Snapshot.status`, `parent_snapshot_id`, `analyzer_versions`, `worktree_digest`; `Relation` carries `resolver`, `confidence_class`, `resolution_status`, `evidence_ids`; `Evidence` carries `extractor` + `extractor_version` + `content_hash`.
- `code_atlas.contracts.enums` defines `NodeKind`, `EdgeKind`, `ConfidenceClass`, `ResolutionStatus`, `SnapshotStatus` matching the Blueprint vocabulary exactly; invalid values rejected by validation.
- `code_atlas.contracts.ports` defines `Protocol` interfaces: `RepositoryScanner`, `ParserAdapter`, `SymbolResolver`, `GraphStore`, `SearchPort`, `IndexCoordinator` — signatures only, no fake implementations beyond what Cycle 1 genuinely provides (scanner from lf-0002, storage-backed graph store minimum).
- `code_atlas.storage` provides: connection factory with WAL, `foreign_keys=ON`, busy timeout; migration runner with `schema_migrations` table and sequential, re-runnable migrations (down optional but forward must be idempotent); `schema_version` queryable.
- Schema tables (per Blueprint §6): `repositories`, `snapshots`, `source_files`, `file_inventory`, `symbols`, `symbol_occurrences`, `relations`, `evidence`, `index_jobs`, `fts_symbols` (FTS5 virtual table created when available; graceful flag when not), plus indexes on `snapshot_id`, `(repository_id, relative_path)`, `(snapshot_id, source_file_id)`, `(from_id, type)`, `(to_id, type)`.
- Index coordinator: `build_snapshot(scan_result)` runs in a transaction — creates `BUILDING` snapshot, writes inventory rows, validates integrity (FK, no cross-snapshot relations), publishes `READY` atomically; on failure marks `FAILED`, preserves prior `READY`, records failure in `index_jobs`.
- Re-running with an identical manifest does not create duplicate inventory rows and does not churn snapshots unnecessarily (no-op or cheap dedup documented).
- All queries parameterized; a test asserts no string-formatted SQL reaches the cursor (audit or convention check).
- Tests: fresh DB migrations, WAL/FK pragmas, snapshot lifecycle happy path, failure mid-transaction preserves prior READY, idempotent re-index, concurrent readers during write, enum validation, relation provenance required fields.

# Constraints

- Stdlib `sqlite3` only — no ORM.
- Do not populate `symbols`/`relations`/`evidence` from real parsing; schema + contract tests only.
- No cross-snapshot implicit relations.
- DB file location comes from config (lf-0001), never inside the indexed repo by default.
