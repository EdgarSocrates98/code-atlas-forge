- Out of scope: incremental semantic invalidation (Cycle 3) — only structural digest/versions awareness here.

# Acceptance Criteria

- New sequential migration(s) (v3+) adding any columns/tables needed for persisted symbols/occurrences/relations/evidence metadata not already covered by Cycle-1 schema — never editing published migrations; checksum-drift behavior preserved.
- `IndexCoordinator.index` extended: after manifest, run parse engine on supported files → build graph → write `symbols`, `symbol_occurrences`, `relations`, `evidence` rows transactionally inside the existing BUILDING→READY publish.
- No-op logic: dedup only when manifest digest AND analyzer_versions (extractor + grammar versions) unchanged; `--full` still forces.
- Batch inserts (executemany) where appropriate; atomicity preserved.
- Parse failure policy: per-file failures recorded as diagnostics + job metadata (file counts parsed/failed); a file-level parse failure does NOT mark snapshot READY-with-silent-loss — snapshot still READY only if failure policy says partial-ok is recorded explicitly in evidence/job stats (decide and document: e.g. `files_failed` counter on snapshot/job + diagnostics rows); fatal engine failure → FAILED snapshot, prior READY preserved.
- Referential integrity validation runs before READY: no dangling relation endpoints, no cross-snapshot relation, FK clean.
- Determinism: re-index same fixture twice → identical persisted symbol/relation ids and counts.
- Tests: integration index of a python+ts fixture repo produces expected counts; failure injection mid-write preserves READY; extractor-version change defeats no-op; batch insert doesn't lose atomicity.

- Keep parameterized SQL only; audit test still passes.
