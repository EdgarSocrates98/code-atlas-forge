# Context

prompt_evo_cycle3.md Phase 0 (0.1 audit, 0.2 scan→parse integrity, 0.3 evidence correctness, 0.4 concurrent consistency). Gate 0: no open P1 on integrity/security/evidence.

Cycle 2 gaps to verify with real code audit:

1. **0.2 scan→parse**: `ParseRequest` reads file bytes at parse time; manifest sha256 was computed at scan time. A file modified between scan and parse is hashed as old content but parsed as new. Fix: verify content identity (compare sha256 of bytes actually parsed vs manifest hash); on mismatch mark file failed/skipped, never publish mismatched identity. Concurrent-modification protection: re-stat/re-read with the same fd discipline used in `_hash_file` (O_NOFOLLOW etc. where portable).
2. **0.3 evidence**: audit `indexing/persist.py` — check whether evidence↔occurrence/relation association uses positional index correspondence that can silently misalign when items are filtered (e.g. evidence referencing occurrences that were skipped). Replace positional mapping with explicit keyed references. Tests: filtered evidence, missing files, relations with multiple evidence.
3. **0.4 concurrency**: two `IndexCoordinator.run()` on the same repo simultaneously; only one valid publication may become READY; last intact snapshot recoverable. Test: concurrent indexers, interruption mid-build, recovery after failure. SQLite single-writer + BEGIN IMMEDIATE is the foundation — verify the actual behavior, fix gaps (e.g. two builders both creating BUILDING snapshots, both attempting publish).

# Acceptance Criteria

- Audit findings documented in the commit/review (what was actually broken vs already safe).
- Parsed content is hash-verified against manifest; mismatch → file marked failed/diagnostic, snapshot still publishable with honest status, never silent wrong-identity READY.
- Evidence associations built by explicit keys (occurrence identity / relation key), not positional zip over filtered lists.
- Concurrent index test: two coordinators racing on the same DB — exactly one READY for a given build attempt; prior READY preserved on loser rollback; FAILED diagnostic recorded.
- Interruption test: coordinator killed/simulated mid-build → no partial READY; recoverable state.
- All existing tests keep passing (182+); new tests added for each fix.
