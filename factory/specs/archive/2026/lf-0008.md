# Context

Parsing must be real — no mocks. Syntactic parsing stays separate from semantic resolution. Files never executed/imported.

# Acceptance Criteria

- `code_atlas.parsers.contracts` defines typed dataclasses/Protocols: `ParserAdapter`, `ParserCapability`, `ParseRequest`, `ParseResult`, `ExtractedSymbol`, `ExtractedReference`, `ExtractedRelation`, `ParseDiagnostic`, `SourceSpan`, `GraphBuildResult` (field list per Phase 1 prompt section).
- `parsers.registry` maps language id/extensions → adapter; lookup by path; unknown → explicit `None`/unsupported diagnostic, never crash.
- `parsers.engine.ParseEngine` orchestrates parse requests: size/time limits honored, per-file failure isolated (one bad file cannot kill a batch), returns `ParseResult` list with diagnostics.
- `parsers.tree_sitter_runtime` is the ONLY module importing `tree_sitter*`; loads grammars via `Language(...)` capsules from `tree_sitter_python.language()` / `tree_sitter_typescript.language_typescript()` / `language_tsx()`; reports parser_version + grammar_version per adapter.
- Adapters implement `ParserAdapter`: python.py, typescript.py, tsx.py — real `tree.parse`, `ERROR`/`MISSING` node detection recorded in diagnostics, byte offsets + line/col preserved, UTF-8/Unicode correct.
- Contracts boundary enforced by architecture test: `code_atlas.contracts`, `discovery`, `storage` must not import `tree_sitter`; parse diagnostics structured (code, severity, span, message).
- pyproject: new runtime deps pinned; `pip install .` works; version bounds noted.
- Tests: real parse of py/ts/tsx fixtures asserting node kinds + spans; invalid syntax yields diagnostics not exceptions; oversized file refused; engine batch isolation.

# Constraints

- tree-sitter usage must not execute analyzed code.
- No network: grammar wheels come from PyPI at install time only; runtime is offline.
- Determinism: same input → same diagnostic + tree summary.

# Review Notes
