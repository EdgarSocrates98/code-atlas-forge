# Grill Gate

- Owner: reuse keyed by full validity key (content hash + language + grammar/parser/extractor/resolver/builder versions + effective config), never by path alone; resolved references not reused when targets/conditions changed.
- Out of scope: cross-machine/shared caches; distributed builds.
- Review failure: a reused result whose inputs actually changed; snapshot corruption on failed build; cache read executing anything.
- Smallest acceptable: versioned per-file parse-result store + reuse in incremental path + corruption/version tests + transactional publication preserved.

# Context

prompt_evo_cycle3.md Phase 5. Validity factors: content hash, language, grammar version, parser version, extractor version, resolver version, graph-builder contract, relevant dependencies, effective config. Snapshot logical isolation despite physical sharing; transactional publish, rollback, recovery, safe GC.

# Acceptance Criteria

- `indexing/cache.py`: persisted per-file result store (SQLite table or sibling DB — choose and justify): key = (repo_id, content_sha256, language, parser_version, grammar_version, extractor_version, resolver_version, builder_version, config_digest); value = serialized ParseResult/subgraph fragment; integrity check on read (stored checksum), version fields recorded.
- `indexing/reuse.py`: materialize reused results into the new snapshot as NEW occurrence/symbol/relation rows bound to new snapshot_id — logical isolation (no sharing of snapshot-scoped rows); identities stable across incremental runs.
- Relations NEVER reused blindly: file-level results may be reused only when its dependency set (imported module digests) is unchanged per planner output; otherwise reevaluate.
- GC: prune cache entries not referenced by the last N snapshots or older than retention policy; safe under concurrent access; never removes rows belonging to live snapshots.
- Transactional build: failed incremental build rolls back new rows, keeps prior READY, records FAILED job — same guarantees as full path.
- Tests: unchanged-file reuse skips tree-sitter call (instrument/count parses); content change invalidates; parser version bump invalidates; config change invalidates; corrupted cache blob detected → treated as miss, not crash; incremental result == full rebuild result (canonical graph equality); failure mid-incremental leaves prior READY intact.
- Schema migration (v4) ONLY if cache lands in SQLite — versioned migration with checksum like v1–v3; document in docs/database-schema.md.

# Constraints

- Serializável, sem pickles inseguros — JSON/structured format only (pickle.loads on untrusted disk data is forbidden).
- Bounded cache size; eviction policy documented.
- No integrity checks disabled for speed.
