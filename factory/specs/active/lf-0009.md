# Context

# Acceptance Criteria

- Python adapter extracts at minimum: modules, classes, functions, async functions, methods, async methods, nested functions, imports+aliases, decorators, declared inheritance (bases), parameters, signatures, docstrings, lexical scope chain.
- TypeScript/TSX adapter extracts at minimum: modules, classes, interfaces, functions, methods, arrow functions when nameable (bound to `const` name), imports/exports, aliases, constructors, declared inheritance (extends), declared interface implementations (implements), type declarations, async functions, relevant JSX constructs.
- Anonymous functions: documented policy — no canonical identity assigned for unnamed expressions; arrow functions get identity only when bound to a name.
- `LogicalSymbol` identity: (language, qualified_name, kind) or documented hash input set — never line numbers; distinct same-named symbols in different scopes must not collide; deterministic across runs.
- `ExtractedSymbol`/`ExtractedReference` populated with `SourceSpan` (start/end line+col+byte offsets), qualified name, scope path, docstring/signature when applicable.
- `ParseDiagnostic` covers extraction-time anomalies (e.g. truncated signature) without aborting whole file.
- Golden-ish unit fixtures (inline source strings) covering: nested defs, decorators, multiple bases, overloads (`@overload`), `import x as y` / `from m import a as b`, TS interfaces+implements, arrow `const f = () => {}`, TSX component, unicode identifiers.
- Deterministic ordering: extraction output sorted stably (by span start, then qualified name).
