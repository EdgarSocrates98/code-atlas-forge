# Acceptance Criteria

- `change_detector.py`: diff(current manifest, last READY snapshot inventory+hashes+analyzer versions) → `ChangeSet` with per-file `ChangeKind` + reason; RENAMED requires sha256 match between deleted path and added path (rename-of-case noted for lf-0021); ANALYZER_CHANGED when parser/extractor/grammar versions differ → affected-language files reclassified MODIFIED.
- `dependency_planner.py`: `InvalidationPlanner` consuming ChangeSet + prior graph (imports/references from last snapshot) → `IndexPlan`: per-file action {reparse, revalidate-relations, reuse, drop} + justification string; dependents of changed modules marked for relation reevaluation even if source unchanged; cycles handled; unknown-dep → conservative reevaluate.
- Transitive invalidation via import edges from the previous snapshot graph (module-level); when no graph available (first index), everything reparse.
- Plan is a serializable, queryable structure (counts by action, per-file reasons) — foundation for `index-plan` CLI later.
- Coordinator integration: `--incremental` path uses plan to skip parsing of UNCHANGED+unaffected files; correctness preserved: affected relations always reevaluated; snapshot publication still atomic.
- Tests: single-file change reparses only that file + relation revalidation of dependents; rename keeps identity (symbol ids stable); delete drops entities; analyzer-version bump reclassifies; no-git repo works; plan JSON serializable.
- Golden-ish regression: modify one file in a small corpus → reindex → resulting snapshot identical to full reindex (same nodes/edges modulo ordering — assert canonical equality).

# Constraints

- Correctness > speed: when in doubt, reevaluate.
- Do not change publication atomicity.
- Keep deterministic ordering in plans (sorted paths).
