- Out of scope: discovery scanner internals (lf-0002), domain models/storage (lf-0003), `index`/`status` full behavior (lf-0004), CI (lf-0005), docs/roadmap (lf-0006). No AST, SCIP, graph, search, impact, MCP, UI.
- Review failure: placeholder/stub functions presented as real; `pip install .` fails in clean venv; missing Apache-2.0 license; CLI commands that error on import.
- Riskiest assumption: zero runtime dependencies is the right call — accepted, stdlib-only (dataclasses, argparse); dev deps only for lint/type/test.
- Smallest acceptable: `pip install .` produces a working `code-atlas` entry point with real `--version`, `doctor` (runtime checks), `init` (writes config), and XDG-aware config with `--root` and `CODE_ATLAS_*` overrides.

# Context

Blueprint v1 mandates a modular, local-first Python 3.12+ package with hexagonal boundaries (`contracts`, `discovery`, `parsers`, `resolvers`, `graph`, `indexing`, `storage`, `search`, `impact`, `context`, `api`, `mcp`, `observability`, `security`). This spec lands the installable skeleton those modules will live in, plus packaging, license, and config plumbing. Repo is currently empty except `factory/` and `.git`.

# Acceptance Criteria

- `pyproject.toml` (PEP 621) builds a wheel; `pip install .` and `pip install -e .[dev]` succeed in a clean venv on Linux; console script `code-atlas` maps to `code_atlas.cli:main`.
- `src/` layout, `src/code_atlas/` package with `__version__`; subpackage dirs created for the bounded contexts that have real code this cycle (`contracts`, `discovery`, `storage`, `indexing`, `observability`) — empty or minimal, no fake logic.
- Runtime dependencies: none beyond stdlib. Dev extras: `pytest`, `ruff`, `mypy` with pinned minimum versions and a `ruff.toml`/`pyproject` config block plus `mypy` strict-ish config.
- `code-atlas --version` prints version; `code-atlas doctor` reports real checks (Python version, sqlite3 version, FTS5 availability probe, git presence, resolved config path) with sane exit codes.
- `code-atlas init [--root PATH]` creates workspace config without deleting preexisting config (refuses or requires explicit flag); config resolves in order: `--root` arg > `CODE_ATLAS_*` env > XDG_CONFIG_HOME (Linux) / %APPDATA% or %LOCALAPPDATA% (Windows) > defaults. No files written into the indexed repo by default.
- Apache-2.0 `LICENSE`, `NOTICE`, `README.md` (pt-BR), `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `CHANGELOG.md`, `.gitignore`, `.github/` issue + PR templates.
- `docs/BLUEPRINT-v1.md` copied verbatim from the operator-supplied blueprint into the repo so specs reference repo-local truth.
- Type hints on public functions; public docstrings; clear CLI error messages; no network calls anywhere.
- Initial git commit lands scaffold + factory specs (local only, no push).

# Constraints

- No external runtime dependencies; no Forge/LLM/Docker/network dependency.
- Do not implement discovery scanning, storage, or indexing logic — that is lf-0002/lf-0003.
- Do not expose `search`, `impact`, `mcp`, `serve`, or `ui` commands.
- No commits or claims of tests that did not run.
- Docs written this cycle in pt-BR; code identifiers and contracts in English.
