# Acceptance Criteria

- Etapa explícita de enriquecimento semântico no pipeline de index()
  (após graph build, antes de persist): ResolverCoordinator consulta
  resolvers registrados por capability.
- Correlação por contexto (arquivo, span, revisão) — nunca só por
  qualified_name.
- `unresolved` sintático promovido a `resolved` quando evidência
  inequívoca existe — com `confidence_class`/`resolver`/proveniência
  persistidos; ambíguo/não-provável permanece não-resolvido.
- Sem duplicação de arestas; arestas semanticas validadas para não
  apontar para ocorrências de snapshot diferente.
- Diagnósticos de falha de resolver no outcome/envelope — operação
  básica preservada conforme política.
- Testes: promoção unresolved→resolved com fixture SCIP; não-promoção
  com evidência insuficiente; coexistência de evidências alternativas
  com política de projeção documentada; determinismo (mesmas entradas
  → mesmo resultado).
